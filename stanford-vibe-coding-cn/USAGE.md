## 一、30 秒快速了解

这是一个**斯坦福大学"氛围编程"（Vibe Coding）系列课程的中文翻译项目**。

- **翻译了什么：** CS146S《现代软件开发者》完整教学大纲、TECH 36 B 教学大纲，以及相关课程信息
- **为什么做：** 斯坦福这门课是 AI 编程领域最前沿的大学课程，但全部内容都是英文，中文学习者获取成本高
- **你能拿到什么：** 现成的中文翻译、统一的术语表、可复用的翻译管线、完整的项目结构

## 三、你可以怎么用

### 场景 A：我只是想学这门课
1. 直接打开 `translated/` 目录下的中文文档
2. 对照 `glossary.md` 理解专业术语
3. 想去看原文的话，对应 `source/` 目录里有英文版

### 场景 B：我想继续翻译，把内容补全
1. 先读 `AAR.md`，了解上一批做到哪了、哪里是缺口
2. 再读 `glossary.md`，严格按照术语表翻译
3. 按照下面的"翻译贡献流程"开始干活

### 场景 C：我想把这个管线用到别的课程上
1. 参考 `AI_LOG.md` 里记录的完整管线步骤
2. 把 source/ 和 translated/ 的命名规范、目录结构直接复制走
3. 换一个课程的资料源，重新走一遍流程

## 四、翻译贡献流程（照着做就行）

### Step 1：认领任务
- 看看 `translated/` 目录里哪些内容还没有中文翻译
- 常见缺口：每周的幻灯片 PDF、GitHub 作业说明、客座讲师讲座字幕
- 在 issue 里认领，避免重复劳动

### Step 2：对照术语表
- 打开 `glossary.md`
- 所有核心术语必须按照表里的译法来，不要自己发明
- 遇到表里没有的新术语？翻译完后补到 glossary.md 里

### Step 3：开始翻译
- **保留格式：** 标题层级、表格、列表、代码块结构和原文保持一致
- **保留原文：** 工具名（Cursor、Claude Code、Warp 等）不翻译，直接用英文
- **首次标注：** 核心术语第一次出现时，用"中文（English）"格式
- **代码不动：** 所有代码块、命令行、配置文件保持英文原文

### Step 4：保存文件
- 英文原文 → `source/` 目录
- 中文译文 → `translated/` 目录
- 命名规则：`主题-章节.md`（英文）和 `主题-章节-zh.md`（中文）

### Step 5：提交 Pull Request
- PR 描述里写清楚：翻译了哪篇、对照了术语表没有、有没有拿不准的地方
- 至少留 1 个 reviewer 审核后再合并

## 五、质量检查清单

提交之前，自己先过一遍这个清单：

- [ ] 术语和 `glossary.md` 一致吗？
- [ ] 标题层级和原文对应吗？
- [ ] 表格、列表格式有没有坏？
- [ ] 代码块和命令有没有误译？
- [ ] 工具名保留英文了吗？
- [ ] 有没有漏译段落？
- [ ] 数字、日期、百分比核对过了吗？

## 六、常见问题

**Q：翻译错了怎么办？**
A：直接提 issue 或 PR 修正，开源项目就是这样迭代的。

**Q：原文官网更新了怎么办？**
A：重新抓取 source/ 里的对应文件，然后同步更新 translated/。

**Q：我可以翻译别的斯坦福课程吗？**
A：当然可以。建议新建一个目录（比如 `stanford-cs336-cn/`），复用同样的项目结构。

**Q：这个项目有授权吗？**
A：翻译内容仅供学习交流使用，原始资料版权归斯坦福大学及讲师所有。如果你想商用或转载，请先联系原作者授权。

## 七、下一步路线图（给愿意深度参与的你）

如果你想成为项目的核心贡献者，这里是建议的进阶路径：

1. **第一阶段（入门）：** 翻译 1-2 篇短文档，熟悉流程
2. **第二阶段（进阶）：** 负责某一周的完整内容（大纲 + 幻灯片 + 作业说明）
3. **第三阶段（维护）：** 维护术语表、审核 PR、处理 issue
4. **第四阶段（扩展）：** 搭建文档站、招募志愿者、对接原作者获取正式授权
