## 讲座一：导论与 LLM 的构造原理

**时间：** 9 月 22 日（周一）
**幻灯片：** [Slides 链接]

### 核心内容

#### 1. 为什么要开这门课？

过去 18 个月里，大语言模型（LLM）彻底改变了软件开发的方式。Cursor、Claude Code、GitHub Copilot 这些工具正在重构开发者的日常工作流。

但问题是：**大学课程还没跟上。** 大部分计算机专业还在教传统的手写代码模式，而行业已经进入了"人指挥 AI 写代码"的新时代。

这门课要回答一个问题：**下一代软件工程师应该怎么工作？**

#### 2. LLM 到底是什么？

大语言模型本质上是一个**超大规模的下一个 token 预测器**。

- 输入一段文本
- 预测下一个最可能出现的 token（词元）
- 把预测结果拼回输入，继续预测下一个
- 循环往复，生成完整文本

**关键概念：Token（词元）**

Token 是 LLM 处理文本的最小单位。它不是一个字，也不是一个词，而是介于两者之间的片段。

例子：
- "tokenization" 可能被拆成 ["token", "ization"] 两个 token
- "strawberry" 可能被拆成 ["straw", "berry"]

**为什么这很重要？**

因为 LLM 是在 token 级别思考的，不是在字符级别。这导致了一些人类觉得很简单的事情，对 LLM 来说很难：
- "strawberry" 里有几个 r？（需要数字符，不是 token）
- 把一个词倒过来拼写（需要逐字符操作）

理解 token 化的原理，是写出好提示词的第一步。

#### 3. 上下文窗口（Context Window）

每个 LLM 都有一个输入长度上限，叫上下文窗口。

| 模型 | 上下文窗口 | 大约相当于 |
|------|-----------|-----------|
| GPT-4 | 128K token | ~300 页 |
| Claude 3 | 200K token | ~500 页 |
| Gemini 1.5 | 1M token | ~2500 页（一整本书） |

**但上下文大 ≠ 效果好。**

研究发现了一个现象叫 **"Lost in the Middle"**（中间迷失）：
- 放在开头和结尾的信息，AI 记得很清楚
- 放在中间的信息，AI 经常忽略或搞错

所以不是把所有东西都塞进去就行，**信息的位置和结构很重要**。

## 讲座二：LLM 强力提示词技巧

**时间：** 9 月 26 日（周五）
**幻灯片：** [Slides 链接]

### 核心内容

#### 6 种核心提示词技术

这一周学的 6 种技巧，是后面所有周次的基础：

**1. K-shot Prompting（少样本提示）**

给 AI 几个例子，让它学会你想要的输出格式。

```
例子 1：输入"你好" → 输出"Hello"
例子 2：输入"谢谢" → 输出"Thank you"
例子 3：输入"再见" → 输出"?"
```

AI 会自动推断出这是中英翻译任务，输出 "Goodbye"。

**2. Chain-of-Thought（思维链）**

让 AI 一步一步思考，而不是直接给答案。

```
问：一个农场里有鸡和兔子，一共 10 个头，28 只脚，鸡有多少只？

不要直接给答案，请一步一步推理：
```

思维链让 AI 在做复杂推理时准确率大幅提升。

**3. Tool Calling（工具调用）**

让 AI 不仅能生成文本，还能调用外部工具（函数、API、数据库查询）。

这是从"聊天机器人"变成"智能体"的关键一步。

**4. Self-Consistency（自洽性）**

让 AI 同一个问题回答多次，然后选出现次数最多的答案。

相当于"多问几遍，投票决定"，适合事实性问题。

**5. RAG（检索增强生成）**

先从外部知识库检索相关资料，再把资料塞进提示词里让 AI 回答。

解决 AI 不知道最新信息、不知道你私有数据的问题。

**6. Reflexion（反思）**

让 AI 先输出一个答案，然后自己评价这个答案好不好，再改进。

相当于"自己给自己当 code reviewer"。

|------|-----------|
| Token | LLM 处理文本的最小单位，不是字也不是词 |
